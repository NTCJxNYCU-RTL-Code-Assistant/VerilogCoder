Implement a Verilog Module named TopModule with listed submodules. The Verilog module implements a configurable bubble sort algorithm designed for sorting an array of data elements. It is structured to support sorting through multiple execution stages, leveraging individual elements known as stages to handle the sorting of data elements.

### Key Functional Components:

1. **Parameters and I/O:**
   - **Parameters:**
     - `N_BITS`: Specifies the bit-width of each data element.
     - `K_NUMBERS`: Determines the total number of elements in the array to be sorted.
     -  The module should be instanced by parameters #(N_BITS, K_NUMBERS)
   - **Inputs:**
     - `clk`: Clock signal to synchronize operations.
     - `rst`: Reset signal for initializing or resetting the sorting process.
     - `load_i`: Controls the loading of individual input data words into the concatenated array.
     - `writedata_i`: Holds the concatenated unsorted input data words for processing.
     - `start_i`: Signals the commencement of the sorting operation.
     - `abort_i`: Provides a mechanism to stop the sorting process if necessary.
   - **Outputs:**
     - `readdata_o`: Outputs the concatenated sorted data from the module.
     - `done_o`: Indicates when the sorting process has been completed.
     - `interrupt_o`: Generates an interrupt signal during specific events or conditions.

2.**Submodules:**
	stageen
	rungenerator
	intgenerator

3. **Sorting Mechanism:**
   - The module uses a series of interconnected stages (`STAGEN`) to facilitate the sorting operation, where each stage handles the comparison and potential swapping of two data elements.
   - Each stage, implemented using the `stageen` module, manages the data passing through it by synchronizing and comparing adjacent elements, eventually leading to a sorted output via iterative operations.

4. **Control Logic:**
   - **Run Generator (`rungenerator`):** Manages the sequence and timing of the sorting operation by controlling a run signal (`run_o`) that dictates when the module should be actively sorting.
   - **Interrupt Generator (`intgenerator`):** Monitors the progression of the sorting process, manages interrupts, and determines when the operation is complete, transitioning to signal `done_o`.

5. **State Management and Signal Flow:**
   - Utilizes signals such as `w_run_up`, `w_swap_up`, `w_bit_up`, etc., to control the stages and dataflow, managing both the sorting process and the output of sorted data.
   - The propagation of these signals ensures that comparisons and swaps are executed at appropriate times based on the bubble sort algorithm's requirements.

6. **Pipeline and Sequential Operation:**
   - The design incorporates a pipelined approach, allowing for parallel processing of data elements through each stage, effectively harnessing hardware resources to manage sorting across clock cycles.
   - Each stage works in synchronization with the clock to ensure coherence in sorting operations and achieves the ultimate goal of a completely ordered data array.

In essence, this module is tailored for scenarios requiring a hardware implementation of the bubble sort algorithm, making it suitable for applications where sorting must be done quickly and efficiently in digital systems, such as embedded systems or hardware accelerators. The design supports scalability through parameterization, enabling adjustment based on specific application requirements."
