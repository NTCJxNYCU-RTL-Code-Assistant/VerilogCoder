I would like you to implement an modules named TopModule with the following interface.
All input and output ports are one bit unless otherwise specified.
input clk 
input rst (Active high) 
input load_i (Multiple bits 1D array. Active high. Control the load of individual data words to writedata_i inside the sorting module.) 
input writedata_i Flattened multiple bits 1D array. Provides new data to the sorting module.) 
input start_i (Active high. Triggers the sorting process.) 
input abort_i (Not used.) 
output readdata_o (Flattened multiple bits 1D array. Expose sorted data outside the sorting module.) 
output done_o (Active high. Indicates the end of sorting process.) 
output interrupt_o (Active high. Indicates the validity of the output data.) 

The module should be instantiated be parameters #(N_BITS, K_NUMBERS)
The module implements the bubble sorting algorithm. It is written in Verilog which should be synthesizable. Do not use the system Verilog.  
The module is intended to be independent of any bus so there is no code to ensure the data transfers. It is left to the user of the module to attach it to the preferred bus. The module is capable of sorting only unsigned words of N_BITS bits.
The user should ensure there are no additional start_i pulses from the beginning of the sorting process until the end of sorting, which is indicated by a pulse on interrupt_o. The user is advised not to read readdata_o until the end of the process, which is also indicated by a pulse on interrupt_o. Information on readdata_o wires is garbage during the sorting process as it reflects the content of registers during the shifting process.

The user should consider the end of the sorting process to be indicated by a pulse of the interrupt_o signal. The signal done_o is exposed to provide an early indication of the process end. The user can tie the done_o signal to the interrupt controller and use it to launch the data reading procedure on a slow system or for systems that have significant latency.


An imaginary use case of the sorting module involves these steps:
bring valid data to the writedata_i; 
load data with a positive pulse on load_i; 
start sorting with a positive pulse on start_i; 
watch done_o or interrupt_o for a positive pulse; 
retrieve data from readdata_o; 
The internal structure is very simple. It resembles a chain and is designed for fast clk. The architecture is a chain of simple modules alongside 2 control blocks. The number of modules in the chain is set by parameter K_NUMBERS.

Submodules:
The control blocks are module 
intgenerator and module rungenerator.
rungenerator: This module is a shift register controlled by start_i and all_sorted_i signals. It starts generating a continuous train of wide 
run pulses when a positive start_i pulse arrives, and stops when brought to stop by the all_sorted_i signal. The 
run pulses are delivered to the K_NUMBERS stages by run_o.
intgenerator: This module is made from an edge select and a counter. It uses the 
run and swap signals provided by the last stage module to decide the end of the sorting process. It stops the wide 
run pulses by the done_o signal, which is generated when a swap indication is missing at the falling edge of the run signal. To indicate all 
readdata_o words are ready, the intgenerator module counts the done pulses and generates a pulse on the interrupt_o signal when it reaches the estimated value.
Stage modules: These modules are made from a shift register and a comparator. The size of the shift register is set by parameter N_BITS. The shift register has parallel load capabilities.
Shift Register: This internal shift register stores a number, let's call it An. It has parallel load capabilities controlled by load_i and writedata_i. It also provides data to readdata_o. Bits of the smallest number resulting from a comparison are stored back into this shift register.
Comparator: This module is inside each stage. During the run pulse, at each clk rising edge, it takes one bit from its shift register and compares it with the bit from the bit_i input. The compare module is self-locking when a valid comparison decision can be done. If An is the number stored in the internal register and Bn is the number arriving at bit_i input, the bits of the largest number of An and Bn will be sent out through the bit_o output to reach bit_i input of the next stage.
During normal operation, assuming unsorted data is already loaded in the module:
At the arrival of a start_i positive pulse, the rungenerator module starts to generate a continuous train of wide run pulses until brought to stop by the all_sorted_i signal. The run pulses are delivered to the K_NUMBERS stages by run_o. During the run pulse, at each clk rising edge, each stage module takes one bit from its shift register and compares it with the bit from the bit_i input. The compare module inside each stage is self-locking when a valid compare decision can be made. If An is the number stored in the internal register of the stage and Bn is the number arriving at bit_i input , the bits of the largest number of 
An and Bn will be sent out through the bit_o output to reach the bit_i input of the next stage. The bits of the smallest number will be sent through value_o to be stored back in a shift register. This makes an 
An number that is not moved by the sorting process to be shifted through the next stage module before being brought back to the holding shift register. This way, at each run pulse, a stage module is comparing an input number with the one stored inside and delivers to the next stage the largest of the 2, just as in the bubble sort software algorithm.
Each stage module also propagates the run signal to the next stage, ensuring parallel operation of stages. The second propagated signal is the swap signal. This is active high and indicates a swap of numbers taking place during the current or a previous stage. Both run and swap signals provided by the last stage module are used by the intgenerator module to decide the end of the sorting process. Just as in software the bubble sort, it is considered achieving the goal when no swapping takes place. The 
intgenerator stops the run wide pulses by the done_o signal, which is generated by missing swap indication at the falling edge of the run signal.
The done_o output of intgenerator linked to the all_sorted_i input of the rungenerator module is only stopping the generation of the run signal. Due to the chain architecture, the run pulses previously generated will continue to propagate from stage to stage. Even if no swapping occurs, the stage modules will be shifting data so that readdata_o will become valid word by word as the run signal moves away. To indicate that all readdata_o words are ready, the intgenerator module counts the done pulses and, when it reaches the estimated value, it generates a pulse on the interrupt_o signal. At this point, the data should be read from the module before writing any new unsorted array.
This sorting module was built with speed in mind, so the clk can be run at high speeds. Running from the clock of the bus will probably be a bad idea. To benefit from the design, a faster 
clk should be dedicated to this module. So, even if this module is presented as a synchronous single clk design, in practice it will end as a multi-clock project.
