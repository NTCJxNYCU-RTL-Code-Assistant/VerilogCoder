## 1. Module Overview

- **Exact module name**: `Omega_Phy_dut`
- **Classification**: Sequential (clocked)
- **Overall purpose**: The `Omega_Phy_dut` module computes the Omega and Phy polynomials based on provided syndromes and Lamda coefficients. Omega is calculated as the product of the syndromes and Lamda, computed modulo 16. Phy is the derivative of the Lamda polynomial.
- **Role within a larger system**: The role is unspecified by the RTL.

## 2. Parameters

> This module has no parameters.

## 3. Ports (Exact and Ordered)

1. **Clock and Reset**
   - `clk`: Input, single bit. The clock signal that drives synchronous operations in the module. Planned to be 56 MHz.
   - `reset`: Input, single bit. Active high asynchronous reset that initializes the module's internal states and outputs.

2. **Control Signals**
   - `Sm_ready`: Input, single bit. Indicates that the input syndromes are ready for processing.
   - `L_ready`: Input, single bit. Indicates that Lamda polynomial coefficients are ready.
   - `poly_ready`: Output, single bit. Becomes high for one clock cycle to indicate Omega and Phy polynomials are ready.

3. **Input Syndromes**
   - `Sm1` to `Sm16`: Inputs, each 8 bits wide. Syndromes provided to calculate the Omega polynomial. Arranged in order.

4. **Input Lamda Coefficients**
   - `L1` to `L8`: Inputs, each 8 bits wide. Lamda polynomial coefficients used for Omega and Phy calculation.

5. **Power and Decimal Memory Interfaces**
   - `pow1`, `pow2`, `pow3`: Inputs, each 8 bits wide. Power values read from external memory.
   - `dec1`: Input, 8 bits wide. Decimal value read from external memory.
   - `add_pow1`, `add_pow2`, `add_pow3`: Outputs, each 8 bits wide. Addresses to power memories for reading power values.
   - `add_dec1`: Output, 8 bits wide. Address to decimal memory for reading decimal value.

6. **Omega Polynomial Outputs**
   - `O1` to `O16`: Outputs, each 8 bits wide. Represent the Omega polynomial coefficients from 1 to 16.

7. **Phy Polynomial Outputs**
   - `P1`, `P3`, `P5`, `P7`: Outputs, each 8 bits wide. Represented as decimal and power values for specific coefficients of the Phy polynomial.

## 4. Behavioral Specification

This module computes two polynomials over multiple clock cycles using a finite state machine:

- **Initialization**: On reset, all internal registers and output signals are cleared or set to their initial values. The module enters `state1`.
  
- **State1 (`Register Inputs`)**: The module waits for `Sm_ready` to capture incoming syndrome values into an Omega register array. If `L_ready` is asserted, it captures Lamda coefficients into a register array and initializes certain Phy outputs. The module progresses to `state2`.
  
- **State2 (`Power Retrieval`)**: The module cycles through a set of predefined operations to load power values corresponding to the syndromes and Lamda coefficients from external power memory interfaces. This occurs over nine cycles, transitioning to `state10` once syndromes and lamda powers are acquired.

- **State10 to State25 (`Omega Calculation`)**: In each state from `state10` through `state24`, the module calculates a specific Omega coefficient (O2 to O16). It uses the power values from the retrieved arrays, adding and conditionally modifying them based on a flag indicating overflow. State transitions occur as specific calculations complete per output.
  
- **State25 (`Power Update`)**: Updates the power values for Omega outputs O2 to O16 by re-retrieving power data from the memory interface, indicating completion with `poly_ready` signal.
  
- **State26 (`Completion`)**: Resets `poly_ready` and cycles the state machine back to `state1` to await new data.

## 5. Timing and Update Semantics

- The module operates synchronously with all transitions driven by the positive edge of `clk`.
- Asynchronous reset sets outputs and internal states to defined initial values.
- Omega and Phy calculations are inherently multi-cycle processes segmented into discreet states.

## 6. Internal Logic Discussion

- **Set and clear behaviors**: Initialization and state maintenance ensure all required calculations and retrievals operate correctly and synchronously.
- **Intermediate storage**: Syndromes and Lamda powers are stored temporarily in registers and accessed during coefficients calculation of Omega and Phy polynomials.

### B. Timing / Propagation Example

When `Sm_ready` and `L_ready` are asserted in `state1`, the input syndromes and Lamda coefficients are captured synchronously on the next clock edge into the internal registers. After processing through the states, `poly_ready` is asserted for a single cycle indicating output readiness.

### C. Complete Behavioral Walkthrough

Leveraging a state machine, the module begins by registering inputs, retrieves necessary powers, then enters a calculated phase where each Omega coefficient (O2 through O16) is determined over multiple states. Derivative Phy polynomial results are calculated in parallel depending on the availability of the Lamda inputs. Once the results are ready, indicated by `poly_ready`, the module can begin the process anew, continuously providing polynomial result calculations as directed by input readiness signals.
